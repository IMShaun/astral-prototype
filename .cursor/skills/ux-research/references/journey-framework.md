# Journey framework

Default **house** journey. Ask first: does this adequately describe the researched experience? If not, use a structure that does. Do not force evidence into these stages.

## House stages

**Pre-service**

| Stage | Meaning |
| --- | --- |
| Wake up | Become aware. |
| Wise up | Find out more, understand, and consider. |
| Join up | Enter the service system. |

**Service**

| Stage | Meaning |
| --- | --- |
| Set up | Prepare the service or product. |
| Start up | Complete the first meaningful use. |
| Keep up | Repeated or habitual use. |
| Mess(ed) up | Resolve problems or incidents. |
| Grow up | Expand, upgrade, or add. |
| Pay up | Pay for the service. |
| Close up | Stop or close the service. |

**Post-service**

| Stage | Meaning |
| --- | --- |
| Speak up | Share the experience. |
| Listen up | Remain connected or informed. |

Enterprise energy work may instead need Discover, Evaluate, Procure, Onboard, Configure, Monitor, Investigate, Report, Administer, Renew. Use that when evidence says so.

## Stage contents

Goals, behaviours, needs, pain points, emotions, questions, channels, archetypes, evidence, insights, KEIs, opportunities.

Accumulate evidence under stages. Do not invent a later prompt or a pain the research has not named.

Desk group `journey` maps in `data/board.json` stay what talks named. Formal journey evidence lives in `docs/research/journeys/`.
