          How you work

          You own the experience layer

          The developer owns the application plumbing. Do not hand over Figma and say build this. Hand over a working React version where the layout, interactions, states, and visual behaviour already exist.

          The path

          Five steps from Figma to a joint check.

          1. Figma Shape the experience.
          2. React UI Make the behaviour real.
          3. Review Developer reads the PR.
          4. Plumbing API, auth, real data.
          5. Joint QA Check it together.

          That is the work. The old path was a prototype thrown over the wall, then a rebuild.

          Your side

          You

          • Visual implementation, responsive behaviour, and design tokens.
          • Components, interactions, animation, and every UI state.
          • Mock data, Storybook stories, accessibility, and UI QA.

          Their side

          Dev

          • API integration, authentication, and permissions.
          • Backend rules, server state, and the database.
          • Error infrastructure, analytics, and application tests.

          How you build

          Stay inside the stack. Pass data in. Build pieces.

          Agree the hangar doors first

          Ask what stack you must stay inside before you write a line. React version, TypeScript or JavaScript, and the component library. Then CSS, folders, and routing. Forms, state, and tests after that, with linting named too. Otherwise you build a beautiful little spaceship that does not fit through the hangar doors.

          Fake data through props
